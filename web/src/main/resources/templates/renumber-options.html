Only for a merge. Neo4j reuses ids of deleted nodes, so some ids of the company's lost nodes may now belong to other nodes on the target. Off: the merge stops when that happens. On: those nodes are restored under new ids (their relationships follow), and every property of the company's nodes that holds exactly the old id as a whole number or as a text of its digits (12 or "12", never 122) is changed to the new id. The dry run lists the new ids and the properties it found before anything is changed.

Above the highest id of the source and the target never reuses an id that ever belonged to a node. Filling the free ids keeps the numbers small, but an id that belonged to a deleted node is used again.

A company node that the source never had cannot hold the old id on purpose: its number most likely means the node that has that id now. They are listed in the dry run and left alone unless this is ticked.
