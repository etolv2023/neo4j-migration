Settings

Choices that different teams make differently.

Temporary servers

A dump, or the data directory of a stopped server, is loaded into a throw-away Neo4j that is deleted when the job ends.

Use the version that wrote your dumps, for example neo4j:5.26.29-community.

Only for “installation on this machine”. Its own configuration and logs are not used or changed.

Needs room for a full copy of each dump that is loaded.

Splitting and merging

The dump files that a split writes are put here. An existing file is never overwritten.

A merge dumps the stopped target here before it builds anything, and keeps the dump. Needs room for a full dump of the target.

The old database is kept next to it and can be rolled back. Switch it off to only write the merged dump file and swap by hand.

Saves writing the whole store as a dump and loading it again. The directory has databases/ and transactions/ in it; copy it into a stopped server's data directory, or add it here as a stopped data directory.

The check reads every record of the new database and can take hours on billions of nodes. Switch it off to save that time: the comparison with the source (counts, ids and a fingerprint of every node and relationship) always runs and catches a wrong copy.

Speed

For databases with billions of nodes. Every value here changes only how fast the work goes, never what comes out.

Loads the dump into a directory and reads the store with the Neo4j kernel on all threads, about ten times faster than asking a temporary server over Bolt. If it cannot start, or the data directory is not writable by this application's user, the temporary server is used instead and the job log says so. A running server (“live”) is always read over Bolt.

The directory made by the build in reader/target/lib. Empty looks for it next to the application.
